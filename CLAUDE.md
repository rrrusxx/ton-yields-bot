# TON Yields Bot

Daily digest of TON DeFi yields (the TON coin was renamed GRAM in June 2026), posted by `@ton_yields_bot` to the public channel `@ton_yields_daily`. Test pair: `@ton_yields_test_bot` posts to `@ton_yields_test`; the local `.env` holds the test credentials.

## Working rules (from the owner)
- Release flow: change → dry run → post to `@ton_yields_test` → the owner checks it in Telegram → commit only when the owner says so → push only on a separate explicit ask (a push to `main` becomes the next production post). After approval Claude may push and trigger `workflow_dispatch` itself.
- Never post to `@ton_yields_daily` and never commit or push without an explicit ask.
- After every finished task update TODO.md, ROADMAP.md, CHANGELOG.md and the relevant `*_INTEGRATION.md`. Leave no debug or scratch files in the repo.
- Explain root causes in plain words, offer options with a recommendation, give copy-paste commands. Numbers are validated against each protocol's own mini app and DefiLlama.
- Post style he set: grouped by asset, then protocol; links only to protocols (never to DefiLlama); no indexer names in rows; the footer lists the data providers (DefiLlama, Swap.coffee, Palette; DeDust and GTC are not credited there, owner's choices of 2026-11-20 and 2026-11-24, `formatSourcesLine` in message.ts); "⛓️ on-chain" appears there only when the post has rows read from contracts (since v1.5.0), and a provider only some rows use (tonapi for TON Whales native staking) only when such a row is shown (`footerCredit`, since v1.7.0); the legend names only markers the post shows, and the post says nothing about referral links (owner's choice of 2026-11-27; the GTC link keeps its referral parameter); APY, not APR; an estimate is marked "est." (`apyEstimate`); no `~` on exact values; low TVL is flagged with ⚠️, not hidden; only impermanent-loss-free yields in asset sections; GRAM-USDT pools in their own section and never in TOP-5. Section names (owner's choice of 2026-11-27): "💎 GRAM YIELDS", "💵 USDT YIELDS" (it also holds the tsUSDe and USDe pools of Ethena, EVAA and Ston.fi; the owner counts them as USDT-denominated and keeps the name, decision of 2026-11-27, so do not raise it again), "🔄 YIELDS FOR GRAM-USDT POOLS". The "Since yesterday" block (v1.8.0) follows the same rules: no GRAM-USDT pools, only rows with $10K+ TVL, no links.
- The repo is public: no secrets, partner-confidential or personal details in code, docs or commit messages.

## Commands
- Dry run (builds the post, sends nothing): run a small script from a scratch directory that has **no `.env`**. `src/config.ts` auto-loads `./.env` from the CWD and refills unset variables, so `env -u TELEGRAM_BOT_TOKEN` alone is not enough. Use `deno run --config <repo>/deno.json --no-lock --unstable-kv --allow-net --allow-env --allow-read --allow-write --allow-import script.ts`, import `fetchTonYields` (`src/services/defillama.ts`) and `formatChannelMessage` (`src/formatters/message.ts`), or `buildDigest` (`src/formatters/digest.ts`: classic HTML, Rich HTML and the snapshot; pass `previous` to see the "Since yesterday" block) by absolute path, write the HTML to a file, then `Deno.exit(0)`. Never import `src/main.ts` or call `sendToChannel`, `sendDigest` or `sendCard`. KV writes land in `./data/kv.db` of the scratch dir.
- `deno task test-msg` and `deno task post` **send** to the channel in `.env` (the test channel locally). `post` sends once per UTC day per channel (a second run that day stops; add `-- --force` to repost). `post` sends the full digest, `test-msg` only a short "Bot is running" message. Use them only for the agreed test-channel step.
- `deno task test`: unit tests (`src/**/*_test.ts`), offline, nothing is sent.
- `deno check --allow-import src/main.ts` passes (grammY 1.45.1 from deno.land/x still pulls `debug` from Skypack, hence `--allow-import`). grammY 1.45.1 is the newest build published for Deno: deno.land/x stops there, JSR has only 2.0 betas, and npm 1.48's `web` build ships Node typings whose AbortSignal clashes with Deno's.
- `deno task start` / `dev` schedule nothing since v1.4.0 (the leftover `Deno.cron` is gone); with a token they only print usage.

## Architecture
- `src/main.ts` (flags `--post-now`, `--test`) → `src/scheduler.ts` → `fetchTonYields()` in `src/services/defillama.ts` (all sources in one `Promise.all`, merge, Palette overrides) → `buildDigest()` in `src/formatters/digest.ts`: `prepareDigest()` in `message.ts` (data, APY and TVL snapshots, TOP-5, sections, shown rows), then `renderClassic()` (Telegram HTML, expandable blockquotes) and `renderRich()` in `rich_message.ts` (Rich HTML tables), plus the post snapshot and the "Since yesterday" comparison (`since_yesterday.ts`) → `sendDigest()` in `src/bot.ts` (grammY; `POST_FORMAT=rich` sends the rich message, classic is the default and the fallback on a 400). After the send: the day's marker, the post snapshot (`post_snapshot.ts`), and on Mondays the weekly card (`src/card/weekly.ts`, `WEEKLY_CARD`), none of which may fail the run. `formatChannelMessage()` stays as the classic-only shortcut. The daily post carries one URL button (`src/formatters/post_buttons.ts`): "How we calculate" opens the channel's pinned post (read with getChat, so the owner must keep the methodology note pinned; without a pin the button is left out). The "Share" button of v1.7.0 was removed in v1.8.1 (owner's choice: Forward does the same, and for a rich post it carries the post itself, while a shared link previews as flattened text). Nothing after the send may throw. The footer time is a `<tg-time>` entity (each reader's time zone).
- `src/services/protocols.ts`: asset families, exact-symbol allowlist `NATIVE_TON_ASSETS` (both ticker generations, plus KTON and STAKED; also the only single tokens allowed in the GRAM section on the DefiLlama and Swap.coffee paths, `isSingleAssetInCategory`; rows built by our own code, such as GTC's "GRAM vault" and the on-chain LSTs, skip it), `HACKED_PROTOCOLS` (rows flagged "🚨 Hacked", no TVL, never in TOP-5), correlated pairs, memecoin and lookalike exclusions, display names and protocol URLs.
- TOP-5: `isTopYieldEligible` / `getTopYields` in `defillama.ts` (known TVL ≥ `config.top5MinTvlUsd` $10K, 0 < APY ≤ `config.top5MaxApy` 100%, not hacked, one place per protocol and asset class; the Storm vault rows take part too, owner's decision of 2026-11-23). On-chain rows reach their groups through `mergeOnchainRows` (by asset class, then `preferOnchain`).
- `src/services/prices.ts`: GRAM price in USD (DefiLlama coins, CoinGecko fallback, null on failure; never guess). Rows whose TVL cannot be priced get `tvlHidden`.
- History: Deno KV `./data/kv.db` via `apy_history.ts` (7d average; pool id = `source-asset-poolMeta`, so renames reset it), `tvl_history.ts` (24h TVL change) and `post_snapshot.ts` (since v1.8.0: what each post showed, key `post_snapshot/<channel>/<date>`, row id = section, protocol and the shown asset text; the next post compares with the newest one before its date, at most 7 days old; a pool is the same pool on both days when its contract address matches, so an on-chain row and its Swap.coffee fallback row count as one, and an APY move is reported only when the APY was measured the same way on both days). Markers: `posted/<channel>/<date>` and `card/<channel>/<date>`.
- Weekly card (since v1.8.0): `src/card/weekly.ts` picks the rows (at least 3 liquid staking rows with an on-chain 7-day APY, never a hacked protocol; stablecoins that pass the TOP-5 rules with $100K+ TVL, by their 7-day value; every number on the card is a 7-day APY and the week named is the 7 days before the post), `weekly_card.ts` lays out an SVG from font metrics (resvg ignores `tnum`, so digits sit in equal slots), `render_png.ts` renders it with `npm:@resvg/resvg-wasm@2.6.2` (WASM read from Deno's npm cache; `initWasm` only once per process). Fonts: Inter 4.1 TTFs in `assets/fonts` with `OFL.txt`. Sent with `sendPhoto`, no sound, Telegram keeps 1600x900.
- Production (since v1.6.0, see HOSTING.md): `.github/workflows/daily-post.yml` has no schedule; a cron-job.org job starts it at 08:00 UTC through `workflow_dispatch` (live since 2026-11-25; a fine-grained token with Actions write, kept only in cron-job.org, expires 2027-11-24; the 08:30 retry job and the healthchecks.io watchdog in HOSTING.md are not set up, owner's choice), and `daily-post-fallback.yml` dispatches it from GitHub's late schedule. Inputs: `target` (production or test, test uses `TEST_TELEGRAM_BOT_TOKEN` / `TEST_TELEGRAM_CHANNEL_ID` only and never saves the KV cache) and `force`. Secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, optional `TONCENTER_API_KEY` (set since 2026-11-20) and `HC_PING_URL` (healthchecks.io watchdog, not set). Repository variables (since v1.8.0): `POST_FORMAT` (classic or rich; set to `rich` on 2026-11-27, owner's decision, so the public channel posts rich messages from 2026-11-28 and he accepts the web-page stub; `gh variable delete POST_FORMAT` switches back) and `WEEKLY_CARD` (monday, off or always; not set), read as `TEST_POST_FORMAT` / `TEST_WEEKLY_CARD` by test runs (HOSTING.md step 5). A run posts at most once per UTC day per channel (`post_guard.ts`, KV key `posted/<channel>/<date>`); `--force` or the `force` input overrides. `./data` is carried between runs by `actions/cache`; entries unused for 7 days are evicted.

## Serverless prototype (serverless/, since 2026-11-27)
- Telegram Serverless runs `serverless/tgcloud/` (plain JavaScript, imports only `sdk` and relative `.js` modules, no npm packages) for the TEST bot only: `handlers/message.js` (`/start`, `/yields` → `sendWidget`), `handlers/widget_query.js` (the widget's tabs: `s:top`, `s:TON`, `s:STABLE`), `handlers/callback_query.js` (`only:TON` / `only:STABLE` → ephemeral reply). Edit `widget/yields.html` and `sample/snapshot.json`, then `npm run build` (Deno) regenerates `tgcloud/lib/widget_html.js` and `lib/data.js`; `serverless/tests/yields_test.ts` checks they are current and that the widget stays under 3,800 bytes compressed (Telegram's limit is 4,096 after zlib level 9).
- The owner enables Serverless in BotFather and logs in to the CLI himself (`npx tgcloud login`; the CLI token lives in `serverless/.tgcloud/`, git-ignored). Never read, print or ask for it. Deploy with `npm run deploy`, then `npx tgcloud webhook sync --drop-pending` on the first deploy.
- Once Serverless owns a bot's webhook, nothing may call `getUpdates` for that bot; the daily post only sends, which is fine. Callback buttons under the daily post may ship only after the production handler is live.

## Gotchas
- Ticker drift drops rows silently. After TON→GRAM, Swap.coffee returns Hipo as `GRAM/hGRAM`; that hid Hipo from 2026-11-08 until v1.4.0. `NATIVE_TON_ASSETS` keeps both generations; add any new LST ticker there (the TON list in `CORRELATED_PAIRS` is reference only). `protocols_test.ts` guards it.
- WSTON is deliberately not in `NATIVE_TON_ASSETS`: the wsTON row is built by the on-chain engine, and listing it would only add DeDust's GRAM-wsTON pool (about 0% APY in November 2026). The cost: if the wsTON read fails there is no fallback row.
- DEX rows (Ston.fi, Tonco, Swap.coffee's own pools, Bidask) never take a token as their label (`DEX_PROTOCOLS` in swapcoffee.ts): Ston.fi pools read v1/v2, Tonco pools "CL" or "CL v1" (concentrated liquidity, explained in the legend). This relabel of 2026-11-27 reset the 7d history of those rows. Affluent is hidden since 2026-11-27 (`DISABLED_PROTOCOLS`, Swap.coffee filter); `HACKED_PROTOCOLS` keeps the flag mechanism.
- Never use substring matching for TON assets (STON, GEMSTON, TONNEL, JETTON, sTONks are not TON).
- `classifyAsset()` puts any symbol it does not know into the GRAM class. A single token stays in the GRAM section only if it is in `NATIVE_TON_ASSETS` (`isSingleAssetInCategory`, also used by `pairBelongsToCategory`) on the DefiLlama and Swap.coffee paths; rows left out are logged. Before this, coffin's one-token markets (HYDRA, KINGY, GRM, durev) reached the posts of 2026-06-01, 06-12, 06-13 and 11-11. GRM is the jetton "Grm", not GRAM: never add lookalikes to the list.
- `config.minTvlUsd` ($10K) is applied on the DefiLlama and DeDust paths (as on DefiLlama's DeDust listing), so their pools under $10K are left out; Swap.coffee ($100) and GTC use lower floors, and their rows under $10K stay in sections with ⚠️ and out of the TOP-5.
- Never log a raw grammY error: a network failure wraps the fetch error whose text holds the request URL with the bot token. Use `describeSendError` (bot.ts), which masks it.
- Telegram HTML: put third-party text through `safeText` in `text.ts` (displayText: one line, no control or direction characters, max 64 characters; then escapeHtml). Use `escapeHtml` alone only for href values; text must stay within 4096 characters after entity parsing; `<blockquote expandable>` cannot be nested.
- APY history keys are `source-asset-poolMeta`, so a ticker rename resets a row's 7d average, and Ston.fi GRAM-USDT rows carry a v1/v2 label so its two pools no longer share a key (DeDust rows are kept unique per pair and label by `keepLargestPerLabel`). The 7d average uses only snapshots dated within the last 7 days (at least 3), so a local KV file with old history shows no 7d values.
- `src/config.ts` loads `.env` with `examplePath: null`: std dotenv otherwise enforces `.env.example` as required keys and silently drops the whole `.env` (token included) when one is missing.
- Custom emoji in channel posts require a Fragment-purchased bot username.
- Bot API 10.1 Rich Messages (`sendRichMessage`: tables, `<details>`, buttons, up to 32,768 characters, 500 blocks, 20 table columns; cells inline-only) work in channels, but Telegram's web renderer does not draw them: t.me/s, embeds, RSS bridges and t.me/s search show "Please open Telegram to view this post" (checked 2026-11-27 on @ton_yields_test post 100, @stables_apy and @kton_channel); only the single-post page keeps a flattened copy in og:description. The API has no fallback-text field. Bot API 10.4 widgets work only in private chats and need a live handler (Telegram Serverless is the no-server option).
- GitHub `schedule` runs start hours late, and public-repo schedules are disabled after 60 days without repo activity.

## On-chain LST and Storm vault rates (implemented in src/services/onchain.ts since v1.5.0)
Realized APY = (rate_now / rate_then)^(365 d / Δt) − 1, where rate = staked GRAM / LST supply from one get-method. Past values come from toncenter v2 `runGetMethod` with `seqno` (archival). The engine uses windows of whole 2-round cycles: the last cycle (131072 s) for the post's APY and 5 cycles (≈ 7.6 d) for its 7d value; `reconcile()` compares them because KTON and Bemo payouts drift up to ~13 min around the cycle. The Storm vaults use one 7-day window (as DefiLlama's adapter), without `reconcile()`; their rate can fall.
